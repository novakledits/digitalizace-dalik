MODUL 1

Jak AI funguje

Jazykový model dopočítává, jaký kousek textu bude následovat. Z té jedné vlastnosti plyne, proč AI umí psát, proč si vymýšlí a proč jí občas chybí paměť.

Co si odnést. Tokeny se platí a tokeny zaplňují kontext. Česky jich obvykle vyjde víc než anglicky, takže stejná myšlenka stojí víc.

Zjednodušená ukázka. Skutečné tokenizery dělí text jinak a každý model má svůj.

Model hádá další slovo

Hotovo

Model ke každému možnému pokračování přiřadí pravděpodobnost a jedno vybere. Teplota určuje, jak moc smí sáhnout vedle nejpravděpodobnějšího. Vyber větu, nastav teplotu a vygeneruj aspoň tři slova.

Zatím jsi nic nevygeneroval.

Co si odnést. Když model látku zná, je rozdělení špičaté. Když ji nezná, je ploché, ale slovo vybrat musí. Tomu se říká halucinace: věrohodně znějící odpověď, která není pravdivá. Rozdíl nepoznáš z tónu odpovědi, jen z ověření.

Ilustrativní čísla. Nevznikla z reálného modelu.

Kontext je paměť s limitem

Hotovo

Model vidí jen to, co se vejde do kontextového okna. Posuň okno a sleduj, co se stane s první zprávou.

Co si odnést. Co se nevejde do kontextu, model nevidí. Důležité věci patří na začátek zadání nebo se musí připomenout. Dlouhá konverzace nezlepšuje výsledek automaticky.

Počty tokenů jsou ilustrativní.

Brief místo otázky

Hotovo

Rozdíl mezi průměrným a dobrým výstupem dělá hlavně množství kontextu, který dodáš. Vyplň pole a sleduj, jak z krátké otázky vzniká brief. Předvyplněný příklad pochází z osnovy, přepiš ho svým.

RAG: odpověď z tvých dokumentů
Hotovo

    
Model sám o tvé firmě nic neví. RAG před odpovědí najde v dokumentech relevantní úryvky, vloží je do kontextu a model odpovídá z nich. Vyber otázku, zapni a vypni dokumenty a porovnej.

Odpověď

    

    
Co si odnést. RAG nenatrénuje model znovu, jen mu před odpovědí podstrčí správné podklady. Dobrá odpověď má zdroj a umí přiznat, že v dokumentech nic není. To si ověř vždycky, zkus otázku, na kterou dokumenty odpověď nemají.

  







  

    
MODUL 2

    
Automatizace a architektury

    
Většina špatných řešení nevznikne tím, že je někdo špatně postavil. Vznikne tím, že se postavila špatná věc. Tady se učíš vybrat správnou, než napíšeš první prompt.

  


  

    
Chat, nebo agent
Hotovo

    
Chat dá jednu odpověď. Agent má cíl, přístup k nástrojům a provede několik kroků po sobě: přečte, rozhodne, zapíše, ověří. Projdi jeden běh agenta, který zpracovává poštu. Vyber, jestli před odesláním potvrzuješ ty.

    

    

    

    
Co si odnést. Agent nespadne. Krok tři vrátí zastaralá data, krok pět je správně naformátuje a výsledek vypadá naprosto věrohodně. Chyba, která hlásí výjimku, je dárek. Chyba, která vrátí hezky napsaný nesmysl, je průšvih. Nevratné akce proto vždy potvrzuje člověk.

    
Scénář je vymyšlený.

  


  

    
API: jak se programy žádají o práci
Hotovo

    
API je dohodnuté rozhraní, přes které jeden program požádá druhý o data nebo akci. Skript, workflow i agent používají API stejně: pošlou žádost a dostanou strukturovanou odpověď. Zkus tři žádosti na vymyšlený sklad.

    

    

      
Žádost

      
Odpověď

    

    
Přístupové klíče a hesla k API nikdy nepiš přímo do kódu, který posíláš modelu nebo nahráváš na veřejný repozitář.

    
Co si odnést. Spouštěče jsou časové (každé pondělí) nebo událostní (přišel tenhle e-mail). Co se spustí, většinou volá API. Čím předvídatelnější odpověď, tím méně potřebuješ AI.

Čtyři C v pořadí
Hotovo

    
Pokud ti z rozhodovací brány agent vyšel, stavíš ho v pevném pořadí. Klikej na karty tak, jak je postavíš. Správné pořadí zjistíš zkusmo.

    

    

    
Co si odnést. Nejčastější chyba je nasadit connections před contextem. Vznikne agent, který má přístup ke všemu a neví, co je důležité. Co je nevratné, řeš s potvrzením.

  







  

    
MODUL 3

    
Digitalizace ve firmě

    
Technologie je ta snazší část. Ve firmě se rozhoduje o tom, jestli se řešení vůbec nasadí, kdo ho zaplatí a kdo s ním bude žít.

  


  

    
Digitalizace, nebo transformace
Hotovo

    
Pracovní rozlišení: digitalizace převádí existující proces do digitální podoby nebo ho zrychlí. Transformace mění to, co firma dělá, jak vydělává nebo jak se v ní pracuje. Zařaď šest situací.

    

    

    

    
Co si odnést. Obojí je legitimní. Problém nastane, když firma říká „transformace“ a udělá digitalizaci, nebo naopak čeká od nového nástroje změnu, kterou nástroj sám nepřinese.

  


  

    
Skeptický decision maker
Hotovo

    
Publikum při pitchi nehodnotí techniku. Rozhoduje, platí a bude s řešením žít. Těchto pět otázek přijde skoro vždycky. Odpověz aspoň na tři vlastními slovy a odškrtni, co odpověď obsahuje.

    

    
Co si odnést. Pilot a MVP slouží k tomu, abys na tyhle otázky měl čísla. Nejmenší verze, která ověří hypotézu, je lepší než největší, která nic neověřila. Když chceš zjistit, jestli lidem pomůže týdenní přehled, pošli jim ho první týden ručně.

Test, který něco dokazuje
Hotovo

    
Prototyp, který nikdo kromě tebe nespustil, je nedokončený. Testuj na třech úrovních a zapisuj čísla. Předvyplněná čísla jsou příklad, přepiš je.

    

      
Self-test
Použij to sám týden na svoje skutečné věci, ne na vymyšlený příklad.

      
Peer-test
Dej to někomu jinému a mlč. Každé tvoje vysvětlení je funkce, která v produktu chybí.

      
Provozní test
Skutečná data nebo uživatelé v malém měřítku. Třeba týden, tři lidé, dvacet záznamů.

Slovníček

  

    
Model
Program naučený na velkém množství textu, který dopočítává, jaký text bude následovat.

    
Token
Kousek textu, se kterým model počítá. Podle tokenů se platí a plní se jimi kontext.

    
Kontext
Všechno, co model při odpovědi vidí: zadání, historie konverzace a vložené dokumenty. Má pevný limit.

    
Halucinace
Věrohodně znějící výstup, který není pravdivý. Model si například vymyslí odkaz na zdroj, který neexistuje. Když ho nejde otevřít, nenapsal ho nikdo.

    
Prompt a brief
Prompt je zadání modelu. Brief je zadání s kontextem: role, materiál, omezení, formát.

    
RAG
Model před odpovědí dostane relevantní úryvky z tvých dokumentů a odpovídá z nich.

    
Agent
Řešení s cílem, nástroji a přístupem k datům, které samo provede několik kroků po sobě.

    
Skript, workflow, agent
Liší se tím, kdo řídí postup. Ve skriptu programátor celý předem, ve workflow programátor s AI uvnitř jednoho kroku, u agenta model za běhu.

    
Spouštěč
Událost, která rozběhne automatizaci. Časový (každé pondělí) nebo událostní (přišel e-mail).

    
API
Dohodnuté rozhraní, přes které jeden program žádá druhý o data nebo akci.

    
Čtyři C
Context, Connections, Capabilities, Cadence. Co agent ví, kam vidí a smí psát, co umí udělat a kdy se spustí.

    
Digitalizace a digitální transformace
Digitalizace převádí a zrychluje existující procesy. Transformace mění, co firma dělá, jak vydělává nebo jak se v ní pracuje.

    
Stakeholder
Každý, koho řešení ovlivní nebo kdo o něm rozhoduje: uživatelé, vedení, ten, kdo platí, ten, kdo to bude udržovat.

    
Pilot a MVP
MVP je nejmenší funkční verze, která ověří hypotézu. Pilot je její nasazení v malém měřítku na reálných lidech a datech.

    
Design thinking
Postup od definice problému přes empatii a ideaci k prototypu a testu. Vždy začíná rozhovorem se skutečným člověkem.

    
HMW
„How might we“, česky „Jak bychom mohli“. Formát otázky, který míří na řešení, ne na překážky.

    
ABT
And, But, Therefore. Tři věty příběhu: kontext, problém, řešení s číslem.
